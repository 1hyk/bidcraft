# 主流程前端页面化重构

日期：2026-10-21

## 范围

将项目理解和检查与补全从抽屉改为工作台主页面，沿用现有接口、编辑器与正文存储。未重新生成正文、调用付费模型或覆盖项目资料。

## 工作流程

1. 项目理解：核对范围、服务内容、对象、招标要求与来源，保存并进入目录规划。
2. 目录规划：左侧目录与要求对应；排版、篇幅设置沿用原有组件；开始编写仍经过生成设置确认。
3. 正文编写：保持现有TipTap编辑器实例和章节目录；保存后进入检查。
4. 检查与导出：技术响应、问题处理在主区域显示；定位正文返回第三步；导出入口收敛至检查页。

桌面采用左侧步骤导航，小屏使用横向导航。文件、公司库、排版、页数和原文详情保留临时面板。

## 数据保护

- 显式选择的步骤不因后台生成状态覆盖。
- 新项目默认第一步；恢复生成任务时进入相应工作页面。
- 切换步骤等待正文自动保存；必要时保存编辑器草稿并回读。保存失败则不切换。
- 项目理解草稿在当前工作台切换步骤时保留；浏览器刷新或离开页面仍可能丢失未保存草稿。
- 分类保存不再要求无意义的第二次确认；保存前后对比招标依据，变化则要求重新核对。
- 刷新项目理解前提示放弃未保存修改；修正要求、保存分类时保留其他未保存草稿。
- 新版组件读取请求增加版本与项目检查，防止迟到响应覆盖当前项目。

## 配套整理

首页筛选只列实际已保存服务类型，移除“常用/其他”分组；编辑场景将建议候选说明为预设选项。

## 验证与限制

前端逻辑测试覆盖四步状态、恢复任务、目录定位、保存顺序、保存失败阻断、依据变更、服务筛选和图片定位。生产构建检查通过。主页面组件通过本地Vite模块接口读取验证。

真实浏览器点击和视觉布局本轮未完成验收（前序浏览器访问受策略限制）。构建与逻辑测试不等同于交互和视觉验收，尤其窄屏目录及长表格仍需实际体验。
