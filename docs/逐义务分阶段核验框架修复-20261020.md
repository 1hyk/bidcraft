# 逐义务分阶段核验框架修复

## 修改目的

避免把“检索到相关正文”直接当作“完整满足要求”。没有针对某份低空标书增加“出现页码就失败”的规则。

## 实现

1. 手动核验时，先仅按招标原文拆分义务，为每项生成稳定ID和检查阶段。引文必须是本条连续原文，且全部义务合起来覆盖原文；漏拆、改写或无效阶段时停止，保留旧报告。
2. 再核对各项正文义务，逐项返回独立证据ID与结论；不能借其他要求的片段，不能漏返回义务却判整条覆盖。
3. 按义务汇总正文覆盖结论；实际导出、提交操作和真实外部证明不能由正文声明证明，保持待对应环节核对，不提前判整条完全满足。
4. 新增“待最终环节核对”状态，界面显示各项原文、阶段及核对情况；不再对所有非错误状态套用“已找到响应证据”的通用通过提示。
5. 当前要求不变时复用经验证的拆分缓存，刷新不调用模型，正文改变后重核无需再次拆分相同要求。
6. 升级检查版本使旧报告过期，不直接把旧covered改造成新框架的已通过结论。

例如“建立索引并填写实际页码”：索引与章节对应属于正文核查，实际页码属于导出核查。找到章节引用只能支持前一项，后一项仍待核对。如果索引本身也没写，仍报告正文不足，不能用“待导出”掩盖。

## 验证

- 新框架9项回归：逐项覆盖、原文遗漏保护、引文与阶段校验、证据隔离、正文不足不被导出阶段掩盖、其他业务多义务、拟议方法提及编页码的正例、数值性能要求正例、拆分缓存失效与复用。
- 编制分流7项、既有质量上下文6项通过；前端生产构建通过。
- 项目21接口正常，旧报告过期，不再拿旧covered当当前结论。本轮没有付费调用模型对业务项目完整重核，也没有改正文或招标要求。

## 限制与后续

- 拆分阶段与正文语义判断仍依赖模型，完整原文覆盖只能防止漏引文，不能保证每次语义拆分都完美；应通过实际多文件核验继续验证。
- “待最终环节核对”不是已实现自动验收。实际页码自动回填、导出后逐项验收尚未在本轮接入；不能据此声称索引页码已经补齐。
- 旧版验证函数保留供旧测试和兼容调用，生产核验调用必须显式传入新义务映射。
- 未提交或推送GitHub。

## 义务拆分失败补漏

用户实际核验出现“义务拆分遗漏原文”。旧实现要求模型重新抄写片段并逐字覆盖全部内容，容易因编号、引导语等未抄齐中断整个流程；原失败响应未落盘，不能断言这次究竟漏了哪一段。

- 服务器现在先保留并编号原文片段，模型仅返回片段编号和检查阶段，不再重抄原文；最终引文从服务器原文恢复。
- 未知编号、遗漏片段和阶段错误仍不放行；失败信息带要求ID、标题和缺失编号。
- 单条失败隔离为该条未核验，不把该条送入后续证据判定或反复付费重试；其他有效条款继续核验。全部失败时保留旧报告并给出具体失败条目。
- 拆分缓存及检查报告版本升级，旧版本结果不继续当作有效依据。
- 新框架12项、编制分流7项、质量上下文6项回归通过。未付费重跑项目21全量核验，未修改正文；实际模型拆分效果仍需下一次真实核验验证。
