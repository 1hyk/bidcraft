# 要求与正文对应检查：使用与验收

日期：2026-10-19。

## 使用入口

工作台 → **成稿检查 → 要求与正文对应**。

1. 打开前先保存当前编辑内容；保存失败会阻止进入检查，避免拿旧正文核验。
2. 首次点击“开始核验条款”；已有报告点击“重新核验条款”。打开或刷新面板只读取报告，不自动重复调用模型。
3. 可按状态、要求类别筛选，或搜索要求和缺项。评分项显示抽取分值。
4. 展开条目，查看解析提取的要求、来源文件与位置，并打开招标原文件核对。提取的要求不是逐字原文的保证；同名文件有多个版本时，不任意链接一份原件。
5. 查看缺项／下一步和正文片段，点击“打开章节”进入编辑器。没有证据时可显示同名建议章节，但标题匹配不作为响应证据。
6. “缺资料与配图”保留原有规则检查结果，也可以跳转到章节。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| 找到响应证据，待复核 | 本次检索中有允许引用的正文片段，模型判断有响应；不代表人工验收或公司能力已证明 |
| 部分响应 | 响应不完整，或引用片段仍有待补／待确认及需核查的能力声明 |
| 未找到证据 | 本次候选片段中未找到，不证明整篇正文绝对没有 |
| 待核实 | 尚未核验、报告过期、调用失败、证据为空或返回 ID 越界等，不能按通过处理 |
| 建议不适用，待复核 | 建议在技术方案以外的投标环节核查，仍需人工确认；不能把资格、报价或投标上传操作一律塞进技术正文 |

## 保存与保护

- 检查产物按项目保存在 `uploads/requirement_reviews/project_<id>.json`，不另建正文存储。
- 保存前核对正文及要求指纹，使用临时文件原子替换；核验期间变化则不覆盖上一份报告。
- 正文、目录、编制设置、要求、所选标段或检查规则版本变化，会使旧报告失效。过期结果不继续显示为当前覆盖证据。
- 模型只能返回当前要求允许的片段 ID。显示的证据文本由服务端读取，模型改写、编造文本不会作为证据原文保存。
- 一个项目同时只运行一次核验；完全未取得有效核验结果时保留上一份报告。
- 关闭后重新打开可继续查看；点击证据跳转前再次检查当前报告版本。

## 当前边界

本功能基于已抽取要求及正文文本候选片段，尚不核验图片内文字、扫描件真伪或资质合法有效性，也不能保证招标要求抽取完整。暂不提供逐条人工签核、逐条重核或自动改写正文。应先处理部分响应和待核实项，再由公司审核可提交性。

真实证据阅读中仍可看到不同章节的功能点总数表述不一致（约 4.6 万、4.8 万、5.3 万）。这是后续跨章节数字一致性核查的具体样本，本轮未修改这些数值，也未把“找到响应证据”表述为数字准确性已验证。
