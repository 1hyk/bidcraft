# 原图编辑链路修正

旧“重新生成”只传原始文字要求与用户反馈，模型看不到当前图。

现有 `/image-assets/regenerate` 改为携带当前素材原图及编辑指令，通过已配置的千问图像2.0接口生成候选。前端改名“修改当前图”，展示原图并允许直接描述修改意见；仍须采用候选后由唯一正文编辑器保存。未自动替换任何已有图片。

## 实现边界

- 原图通过Base64传输，不要求公开本地URL，不上传其他素材。
- 校验素材像素ID、路径和大小；不支持的模型明确失败，不静默退回文字重画。
- 编辑提示保留未提及的构图和内容，以用户反馈为优先，避免旧提示覆盖新意见。
- 输出尽量保持原图长宽比；像素按接口要求取16的倍数。
- 缓存包含原图身份和编辑模式，候选保留来源素材ID及修改意见，不持久化原图Base64。
- 不自动重试付费请求，不承诺像素级保持不变。

## 验证

19项图片链路测试、35项前端测试通过；前端生产构建通过。测试验证HTTP请求同时含image和text、原图编码一致、原图不被覆盖、编辑缓存及失败不退回盲画。项目27界面已实际打开并检查原图及修改入口。本轮没有提交真实付费编辑，尚未验证模型对某条虚线的实际去除效果。

接口依据：[阿里云千问图像编辑API](https://help.aliyun.com/zh/model-studio/qwen-image-edit-api)。

## 后续真实复验

### 双模式及 Mermaid 单图修改

- 普通图片保留“修改当前图”，新增“重新设计一张”：视觉模型读取当前图和修改意见，组织新场景提示，再调用文生图；不伪装成局部编辑。
- Mermaid 新增“AI修改本图”：传入源码、章节上下文与修改意见，返回单图候选，经浏览器 Mermaid 实际渲染后才允许采用。支持“根据本章重新设计”，不重写整章。
- 两类候选均须主动采用；候选生成不改变正文。
- 重新设计真实复验生成 2048×1536 图片，人工查看未见无人机之间的黑色虚线和无线信号图标，构图已经变化。这证明本次重新设计指令有效，不代表此前局部编辑通过。候选未应用正文。
- 证据：`uploads/_verification/drone-redesign-live-20261021.json`、`mermaid-edit-live-20261021.json`。新增 Mermaid 服务测试 3 项通过；图片测试 19 项、前端测试 35 项及生产构建通过。
