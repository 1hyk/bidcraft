# 正文响应与编制排版分流修复

## 问题

项目21要求507“响应文件格式”原文为：响应文件格式详见附件2。技术方案部分应按照附件三评审办法的方案要求自行编制。

旧核验将其判为部分响应，并推导出正文应证明字体、页边距、装订和逐条索引。上述判断混合了实际版式、提交检查与技术内容覆盖；缺少声明不等于实际排版错误，附件指引也不自动等于必须提供逐条索引。

## 系统修改

- 编制要求按句区分：纯附件编制指引、版式要求进入独立“编制与排版提醒”，不计正文缺项，也不自动判为合格。
- 混合要求保留具体技术义务参与核验，原始提取内容不改、不删除。
- 接口报文格式、明确索引/响应表、评分项及具体测试义务保护为技术核验，避免遇到“附件”“格式”就整条豁免。
- 核验提示禁止从正文推断实际排版，禁止为附件引用擅增未明确要求的索引或格式证明声明。
- 检查版本升级使旧报告失效，防止旧误判继续作为当前依据。

## 验证

- 新增分流7项、既有质量上下文6项、招标要求目录覆盖9项通过；前端生产构建通过。
- 项目21真实接口：要求507为`compilation_check`，`missing_points`为空，不再呈现旧“部分响应”结论；20条技术要求仍在技术核验范围，另有1条编制提醒。
- 未修改正文、未更改招标要求原记录、未付费重跑模型。其余旧核验因规则变化显示过期，需要按新口径重新核验，不能宣称全部响应通过。
- 这不是自动排版验收功能；附件条款及实际导出格式仍需核对。
