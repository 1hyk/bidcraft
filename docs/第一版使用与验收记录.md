# 第一版使用与验收记录

日期：2026年10月18日。范围：主流程减负、公司资料提炼、有来源补全建议及安全撤回。

## 已完成

- 目录和全文生成不再要求先确认项目理解；项目理解仍可查看及修正。
- 新建项目的业务信息收进可选区；标段确认后直接进入工作台，不再强制进入业务确认页。
- 公司资料支持上传、去重、后台提取、失败重试、原件回查、候选核对、启用、否决和停用。
- 支持 docx、文字型 PDF、xlsx、单张 png/jpg 图片。图片先转录文字，所有事实仍待人工核实。
- 事实保留主体、字段、原文值、证据、位置、有效期、限制和修订版本。候选、过期、停用、来源提取失败的事实不作为确定依据。
- 明确单值的公司身份字段发生冲突时阻断；多张证书、多项业绩不简单视为互斥，匹配歧义保留人工核对。
- 已核实事实进入生成上下文；工作台“资料补全”可按章查找待补充与待确认标记，展示建议值、理由及原件依据。
- 模型只推荐已核实事实编号；替换值由服务端从该条事实读取，不采用模型自由编写的替换事实。
- 应用所选建议后记录修改前后载荷及事实快照；正文、公司基本档案或事实修订已变化时拒绝旧建议。
- 涉及本次负责人、资源投入或服务时限等安排不直接从公司资源池决定。
- 撤回需当前正文与应用后版本一致；有后续人工修改时拒绝覆盖。多次补全可逆序撤回。
- 保存编辑器正文时保留原有取材及历史元数据；补全操作不触发经验自动提炼。
- 公司新原件和项目理解元数据移至非静态目录；旧公司静态路径封闭。本版沿用本机应用的访问模型，不是多租户权限系统。

## 如何使用

1. 打开“本公司资料”，上传公司介绍、证书或业绩资料。上传后等待状态从 extracting 变为 extracted；失败会显示原因，可重试。
2. 在待核实区对照原件，修改主体、字段、事实值及有效期，点击“已核实，启用此事实”。不确定的继续保留待核实。
3. 公司名称可在基本资料中填写；也可通过已核实、无歧义的公司名称事实辅助匹配。未明确主体时，系统可能保守拒绝补全，不应靠放宽校验强行填入。
4. 正常生成技术方案，不必先建设完整公司档案；缺少事实依据的内容继续标记待补。
5. 已有正文中，点击工作台“资料补全”，选择章节，查找建议，核对建议和来源后勾选应用。
6. 在同一抽屉的修改记录中撤回；若正文有后续修改，应先处理后续补全或人工修订，系统不会强行恢复旧稿。

打开补全前会保存当前编辑并临时锁定编辑器，降低同一页面的保存竞态；其他标签页或客户端的后续编辑仍由应用前校验及撤回检查保护。

- `tests/verify_company_v1_database.py`：真实MySQL事务测试，使用连接级临时表；验证候选不应用、应用回读、元数据保留、后续人工修改保护、安全撤回及冲突阻断，不改变真实项目。

- 主体未明确的探针曾被模型拒绝；保留这一安全行为，并补充了公司主体信息进入匹配的链路。
- 原有项目分类、知识页适用性、领域提示词隔离、技术方案生成范围及项目理解回归通过。
- 页面实查：公司资料页、核对表单、资料补全抽屉可打开；无公司事实时不伪造建议。

## 已知限制

- 扫描PDF或含不可读扫描页的混合PDF明确失败，不做不完整提取；可提供文字版或将页面按图片上传。DOC旧格式暂不支持。
- Word内嵌的扫描证照图片暂不自动OCR，需将证照作为单张图片上传；不要将正文提取成功理解为全部内嵌图片已识别。
- 单文件25MB、PDF最多200页、xlsx单表最多10000行、单份资料提取文字最多18万字符，超出明确提示拆分。
- 第一次提取使用已配置模型，网络、额度及模型服务影响任务时间；原件仍保留，可重试。
- 第一版逐章补全，每次最多处理80个标记，不做无人审核的整篇自动回填。
- 跨HTML标签拆开的待补标记暂不能识别；需要在编辑器将其整理成连续文字后重试。
- 公司事实的模型匹配仍可能漏选或误判，最终应用需人工核对；未做多候选资源自动任命、完整跨资料语义冲突推理及事实真实性认证。
- 对大规模资料上下文设置预算，未进入本次上下文不表示资料不存在；可按待补项进一步检索。
- 补全和撤回保护本次修订，不替代所有编辑入口的完整版本控制系统。
- 当前仅本公司单主体使用。没有新增多公司、跨行业共享、统一大图库、补遗自动重写等后续阶段功能。
- 未重新生成现有项目全文，也未以本轮公司事实补全改变现有技术方案正文。原知识库及图片数据保留。

## 安装与迁移

已有环境执行：`.venv\\Scripts\\python.exe scripts/migrate_company_v1.py`，再启动后端与前端。

新环境的 `scripts/check_env.py --init-db` 会创建公司资料表；旧JSON档案使用上述迁移脚本导入。迁移前将存在的旧档案备份到非静态数据目录；脚本重复执行不覆盖当前公司档案。

新增表：company_profile、company_document、company_fact、company_fill_revision，结构定义在 `scripts/company_v1.sql`，均带中文COMMENT。资料文件及签名密钥放在 `data/company/`，项目理解元数据放在 `data/company_workspace/`；整个data目录已忽略提交。

原件、事实、修订相互关联，故回滚不得只删除某张表或清空data目录。需要回滚时先停止新写入，备份新增表及data目录，保留原库和正文，再针对具体迁移处理；本版没有执行破坏性整库迁移。
