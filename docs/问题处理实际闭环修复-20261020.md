# 问题处理实际闭环修复

## 行为调整

- 取消通用“不适用”。已有旧记录保留，但不再据此隐藏问题。
- 图片可直接进入替换入口，或进入正文移除确认；打开入口不算完成，取消也不关闭。
- 替换操作记录保存前素材集合。复查时原素材已离开且有新增引用，才显示当前正文已完成替换，并记录新素材ID；仅删除不冒充替换完成。
- 移除需正文真实移除原素材；原素材文件保留。此操作完成不代表招标必需配图要求已经满足，技术响应仍需独立核查。
- 新图自身的质量问题独立继续提示；人工可确认图片可用或报告误报，必须填写依据。
- 真实缺项、空正文、缺图、缺表、重复图片及页数问题不能靠人工确认按钮直接关闭；须实际修改并复查。
- 修改正文待办在复查不再检出原问题后进入已处理记录。
- 历史人工确认仍绑定内容指纹；相关内容变化后需要重新核对。

## 验证

- 闭环专项10项、质量上下文6项通过；前端生产构建通过。
- 项目21旧图片“不适用”真实记录已恢复为待处理，原操作记录保留。
- 浏览器实际点击“替换／修图”，自动定位图片并打开替换对话框；关闭保留原图后，检查接口仍返回该问题待处理、替换操作为pending，没有误关。
- 验证过程中未采用候选、未删除图片、未生成图片或重写正文。只增加了“请求替换”的待办操作记录。
- 当前实现按同章新增素材引用识别替换，不是完整编辑事件日志；复杂的多图同时增删需人工核对记录，不能视为逐图语义审核。
- 项目内的替换入口仍提供素材选择、上传与重新生成；自动局部擦字尚未接入，按钮不代表已经实现局部修图模型接口。
