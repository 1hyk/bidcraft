# 项目理解业务提取与稳定读取修复

日期：2026-10-20

## 问题

- 服务类型只能命中软件候选词，车辆维修项目被错误归到运维、培训。
- 每次点击都会重新调用模型提取工作对象，结果粒度和措辞变化。
- 提取建议、人工保存值缺少明确区分；正文生成未统一注入已保存的业务与工作对象。

## 处理

- 实际服务类型允许原文业务名称，预设选项仅作输入辅助；领域继续控制历史素材范围。
- 主营业务与总体工作对象在同一次模型请求中提取，引用逐条校验到当前项目、当前标段的招标或澄清原文。
- 保存项目与标段隔离的建议版本；同一来源版本重复读取不调用模型。主动重新提取生成新版本，保留最近五版历史。
- 来源变化或提取期间标段切换，不把结果作为当前有效建议保存。提取异常不覆盖上一版。
- 查看建议不改项目字段；采用到表单后，明确保存才更新项目。允许人工输入实际服务名称。
- 目录及正文上下文使用已保存值，未采用建议不进入编制。
- 首页服务类型筛选只展示项目实际使用的类型。

## 验证

- 8项业务摘要测试：跨业务、引用校验、缓存、失败保留、来源变化、项目/标段隔离、读取已保存值等。
- 8项项目分类与保存接口测试通过；前端生产构建通过。
- 项目19真实页面采用并保存“车辆维修和保养”与“车辆”，重新打开保持一致。
- 三次重复接口读取内容、版本、时间一致；主动重提取版本2到版本3后，已保存字段不变。
- 版本3的业务名称为“车辆维修和保养服务”，说明模型重提取措辞仍可能变化；稳定性由版本保存和显式采用保证，不宣称模型重复输出逐字一致。
- 已验证生成上下文包含项目19的已保存字段。本轮没有重新生成完整技术方案。
