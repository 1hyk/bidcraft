# 问题处理与配图分流修复

日期：2026-10-20

## 本轮实施

| 问题 | 修复 |
| --- | --- |
| 人工核对后问题反复出现，无处理记录 | 增加“已人工核对”“不适用”“重新打开”；填写处理说明，显示已确认事项及历史操作记录 |
| 确认后正文或图片变化，旧确认可能误导 | 处理记录绑定章节内容、配图文件、素材元数据的指纹；变化后重新进入待处理；提交旧页面的确认返回冲突提示 |
| 处理事项与技术覆盖结论混淆 | 处理记录独立保存，不修改正文，不把技术要求自动标为通过；原始待补标记数量仍显示，不能靠确认按钮清除正文占位 |
| 排班等内容按图名分流，通用性不足 | 思路生成增加内容来源和数据结构；分配、记录、对照、测量数据用表格，时间跨度用甘特图，流程与层级关系用 Mermaid，空间场景才走插图；旧思路兼容原规则 |
| 实物场景提示过于泛化 | 思路提示明确要求主体、数量或规模、相对位置、视角、关键细节；禁止整段正文充当画图说明，禁止把图名画入图片 |
| 同名历史图片可能被直接认领 | 取消图名完全相同即可绕过内容核验的捷径；未明确绑定素材ID时，同名候选仍需内容适用性核验 |

## 存储与限制

- 人工记录保存在 `uploads/issue_resolutions/project_<项目ID>.json`，采用进程锁与原子替换，当前单后端进程使用。部署时须持久化该目录；多进程/多实例写入应迁移数据库事务或共享锁。
- 自动消失的问题不需要人工确认；历史人工操作仍可查看。
- 证据指纹采取保守策略：同章内容或关联配图变化可能要求重新核对，不保证只重开最小的一句话。
- 新的结构字段由后续思路生成填写，不能保证模型分类永远正确。旧思路仍有名称规则兜底，本轮没有批量重跑思路。
- 没有增加向量库，没有宣称历史图片匹配准确率已达到某个数值。
- 实物图实际视觉效果仍需下一轮生成样本确认；长图拆分与布局优化未在本轮完成。
- 未提交或推送 GitHub。
