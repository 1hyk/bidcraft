# 检查与补全统一流程

## 本轮框架

工作台按项目理解、目录与排版、正文、检查与交付分组。移除顶部独立资料补全入口，统一由“检查与补全”承接。公司资料库为长期辅助资料入口，不作为开工必填步骤。

统一面板保留两个职责：要求与正文对应（人工启动条款核验）、问题处理（规则检查、分类与定位）。问题分类包括待补资料与安排、事实与承诺、人员归属、图片、页数及其他。

从待补问题进入公司资料补全时，携带对应章节；补全仍须查看原件依据并手动选择应用，支持已有撤回机制。应用或撤回后刷新规则清单与核验版本状态，不自动把条款标记为已响应。公司库有效资料数量仅表示库存，不等于本项目覆盖率或实际引用数量。

实际参数、本次人员安排及非必要细节并非都要上传公司文件。界面明确区分可查库事实、需要确定的项目安排、可回正文改写的细节。此轮未增加自动判断所有待补项性质的模型，也未增加一键自动修稿。

## 后续推进边界

生成时实际采用的公司条目逐条追踪、招标必需证明的生成前匹配、逐条待补分类以及项目安排确认表，仍需分别设计与验证。本轮统一入口不代表这些能力已经实现。现在可通过已有原件、公司事实审核和补全记录追溯人工应用依据。
